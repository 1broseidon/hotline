## Description
Split hotline-core into crates, in stages, on release/0.41.0. George asked for it 2026-10-19 after the post-0.40 sniff test (epic-15 point 2): one 163k-line crate with 58 dependencies, whose module boundaries nothing enforces, and whose front end (type and borrow checking) runs on one thread. The goal is enforced boundaries and faster incremental builds; CI gains are expected to be modest (rust-cache keeps dependencies, not workspace crates), so each stage is measured, not assumed.

What the code looks like (release/0.40.0, `crate::X` references between top-level modules):
- True leaves today: contract (its one `crate::paths` mention is a doc link), credentials, process_windows, images, fence, room_lock, websearch (contract only), spending, link_preview, skills (contract, paths).
- Nearly free, one link each to cut: paths → linked (`linked::is_linked`, a string test), log → credentials (`atomic_write`), store → thread (`Link`, `ThreadState` types) and sent, tools → driver (`CapabilityLease`, `CapabilityEpoch` types).
- One strongly connected core: session, voice, driver, wire, mcp, room, vault, remote, computer, desk, providers, imagegen, import, models, capabilities all reach each other. Splitting it needs trait seams (wire already talks to a `RoomHandle`), which is design work: this epic plans it and does not start it.

Rules for every child:
- Moves only: no behaviour change, no renamed wire field, no new dependency beyond the new workspace crates. Public paths inside hotline-core may keep working through `pub use` re-exports while callers move.
- `ui/src/generated/contract.ts` stays byte-identical (`git diff --exit-code`), generated by an unfiltered `cargo test` (AGENTS.md trap: a filtered run truncates it).
- docs/security.md citations follow moved code (the precheck citations leg refuses a stale one); docs/standards.md's module map and AGENTS.md name the new crates; hotline-core keeps no Tauri.
- Each new crate gets the workspace `[lints]`, a license, and a crate-level doc saying what it owns and what it must never depend on.
- `make check` and `make precheck` pass before landing; one-line commit messages stating the invariant.

Done when: the leaf crates are out, the store and tools crates are out, before/after build timings are recorded, and an ADR proposes how the core is split next, for George to decide.

Not started without George: anything in the core cycle beyond the plan.
