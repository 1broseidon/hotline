## Description
A local pre-CI gate that catches ~95% of what fails on GitHub's runners, so CI cycles aren't wasted (George, 2026-10-17). Everything runs on this Mac (Mac Studio). Grizzly is being decommissioned; CI already uses hosted runners (repo var CI_RUNNERS=hosted).

Why: every 0.39.0 CI failure was something that only breaks elsewhere:
- Windows: test helpers used only under cfg(unix) failed as dead code with -D warnings.
- Linux bun: ui/tests/voice-desk-dictation.test.ts relied on a `window` another file left defined (order-dependent).
- Hosted macOS: python3 inside the macOS shell sandbox never served (task-89), only on the runner.

CI today (.github/workflows/ci.yml, workspace-isolation.yml):
- `cargo clippy --workspace --all-targets --locked -- -D warnings` and `cargo test --workspace --locked` on Linux, Windows and macOS-26;
- `make check` on the isolation job;
- bun install --frozen-lockfile, plus scripts/fetch-speech-engine per target.

Build:
- **`make precheck` (fast, a few minutes, warm).** Run it before pushing any PR or release branch, and make it the landing check (brainfile contract / make check, whichever the landing runs).
  - cargo fmt --check;
  - `--locked` lockfile drift;
  - generated files match (ui/src/generated/contract.ts regenerated by the unfiltered test, diff empty; mind the filtered-test truncation hazard);
  - clippy -D warnings --all-targets for the host and for **x86_64-pc-windows-msvc via cargo-xwin** (brew llvm/lld as needed; ring and aws-lc-sys must build; if a crate can't cross-build, check what can and say what's skipped);
  - each ui test file run **on its own** (`bun test <file>`), plus the normal full run;
  - actionlint on .github/workflows.
- **`make precheck-full` (before a release PR):** precheck, plus:
  - **Linux**: clippy -D warnings and `cargo test --workspace --locked` inside an Ubuntu 24.04 container via Apple's `container` CLI (/usr/local/bin/container 1.5.0, running; there's no Docker CLI on PATH). Use a persistent cargo target/registry volume so it's warm, with the repo mounted read-only plus a writable target. Mirror CI's packages and fetch-speech-engine for linux.
  - The integration tests with a runner-like bare PATH (no mise/uv/homebrew python first), to catch tool assumptions like task-89's.
  - One shuffled test run (`-Z unstable-options --shuffle` on nightly if available, else run twice) to catch order and temp-path collisions.
- Scripts live in scripts/precheck* and are idempotent. They print per leg pass/fail with time, and the exact command to rerun a failed leg. Missing tools are installed with brew or rustup and announced, never silently.
- docs/development.md: what each leg catches, how to run it, and how long it takes warm and cold.

Done when, run on the 0.39.0 failing commits:
- precheck catches the Windows dead-code failure (2ab8e33d's parent, 7b1fe52a) and the ui window failure;
- precheck-full's Linux leg passes on today's release/0.40.0;
- warm times are recorded.
